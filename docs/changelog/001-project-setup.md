# 001. Перенос проекта в репозиторий

**Дата:** 2026-10-07
**Коммиты:** `698254b` (перенос), `40e57c7` (уточнение CLAUDE.md), а также коммит с этим файлом

## Что сделано

- Проект перенесён из рабочей папки `Desktop\Pet_Simulation` в git-репозиторий и опубликован на GitHub (приватный репозиторий `yachiro19/pet-simulation`).
- Файлы разложены по папкам: `src/`, `include/`, `macros/`, `analysis/`, `docs/`.
- В `CMakeLists.txt` путь к Geant4 сделан переопределяемым, макросы теперь автоматически копируются рядом с исполняемым файлом.
- Добавлены `README.md`, `requirements.txt`, `.gitignore`, `CLAUDE.md` и быстрый проверочный макрос `macros/test.mac`.

## Зачем

- Сохранить рабочую версию кода с историей изменений: дальнейшая работа над дипломом должна быть отслеживаемой и обратимой.
- Отделить исходный код от артефактов сборки. В рабочей папке исходники, файлы Visual Studio, `.exe` и результаты расчётов лежали вперемешку, а актуальные версии скриптов были только в папке сборки `build2/Release`.
- Сделать так, чтобы проект собирался не только на одном компьютере: на другой Windows-машине или на Linux.

## Как

**Выбор файлов.** C++ исходники взяты из `src/` и `include/` рабочей папки. По проекту Visual Studio в `build2` проверено, что рабочий `.exe` собран именно из них: время изменения `.obj` совпадает с правками `.cc`. Скрипт анализа и макросы взяты из `build2/Release`, потому что там лежат рабочие версии:

| Файл в репозитории | Источник | Примечание |
|---|---|---|
| `analysis/analyse.py` | `build2/Release/analyse.py` | Работает с колонками `NumGammaHits` и `PhotonCount`, которые пишет текущий `EventAction.cc`. Старый `analyse.py` из корня ждал колонку `NumHits` и с текущими данными не работал |
| `macros/run.mac` | `build2/Release/run.mac` | Перекодирован из CP1251 в UTF-8, чтобы комментарии читались на GitHub и в любом редакторе |
| `macros/batch.mac` | `build2/Release/batch.mac` | 50 000 событий без визуализации |
| `docs/PET.pdf`, `docs/PET_Report.pdf` | корень рабочей папки | Презентация и отчёт |

Не перенесены: папки сборки `build/` и `build2/`, результаты (`pet_data.csv`, `pet_results.png`), устаревшие макросы `run_batch.mac`, `vis.mac`, `vis_fixed.mac` и шаблон `vis.mac` из примера Geant4 B1.

**CMakeLists.txt.**
- Путь `C:/Geant4/geant4-v11.3.0-inst` остался значением по умолчанию только на Windows и переопределяется через `-DGeant4_DIR=...`.
- Добавлен шаг POST_BUILD, который копирует `macros/*.mac` в папку с исполняемым файлом. Это нужно, потому что `main.cc` ищет `run.mac`, а `EventAction` пишет `pet_data.csv` в текущую папку.

Код C++ и логика анализа не менялись.

## Проверка и результат

- Сборка: CMake 4.0 + Visual Studio 2022, Geant4 11.3.0, конфигурация Release, без ошибок.
- Запуск: `PET_simulation.exe test.mac` (100 событий) отработал за ~23 с с кодом возврата 0, `pet_data.csv` создан.
  - Сначала запуск блокировал Smart App Control в Windows 11 (неподписанные DLL Geant4, код `0xC0E90002`). После его отключения симуляция работает.
- Анализ: `analysis/analyse.py` отработал на полученном `pet_data.csv` и построил `pet_results.png`.
- Наблюдение: в CSV попадает лишь ~1–2 % событий. Источник изотропный, а кольцо из 24 кристаллов высотой 10 мм покрывает малую долю телесного угла (по азимуту ~28 %, по высоте ~4 %). Для статистики нужны десятки тысяч событий (`batch.mac`).
