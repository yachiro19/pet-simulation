# 004. Режим tof: макросы сканирования и параллельный запуск

**Дата:** 2026-10-07

## Что сделано

- Макросы режима tof (`macros/tof/`):

  | Макрос | Назначение |
  |---|---|
  | `config_default.mac` | все параметры с комментариями и число событий на точку |
  | `scan.mac` | скан положения источника −3…+3 мм с шагом 1 мм |
  | `compare.mac` | материал × форма × положение в одном процессе |
  | `vis.mac`, `test.mac` | визуализация и быстрая проверка |

- Скрипт `scripts/run_tof_campaign.py` запускает конфигурации параллельно, отдельными процессами.
- Замерено время счёта; число событий по умолчанию — 20 000 на точку.
- Каталоги результатов (`results/`, `tof_output/`) добавлены в `.gitignore`.

## Зачем

- Оптические фотоны — самая дорогая часть расчёта, поэтому нужен batch-режим без визуализации и понятная оценка времени счёта.
- Программа однопоточная (`G4RunManager`), а процессор 12-поточный. Проще и надёжнее запускать независимые конфигурации параллельными процессами, чем переводить код на многопоточный Geant4: в многопоточном режиме пришлось бы разделять выходные файлы и состояние генератора между потоками.

## Как

**Скан положения** использует встроенные циклы Geant4:
- `scan_positions.mac`: `/control/loop tof/point.mac zpos -3 3 1`;
- `point.mac`: `/tof/source/z {zpos} mm` и `/run/beamOn {nev}`.

При смене положения геометрия пересобирается (источник — физический объём), и каждый прогон пишет свой CSV.

**Полное сравнение** — вложенные циклы: `compare.mac` → `/control/foreach` по материалам → `/control/foreach` по формам → скан положения.

**Параллельный запуск** (`run_tof_campaign.py`):
- Для каждой пары «материал × форма» скрипт генерирует макрос и запускает отдельный процесс `PET_simulation -m tof`. Одновременно работают `--jobs` процессов, по умолчанию 6.
- Форма задаётся строкой `name[:taper[:narrowEnd]]`, например `trd:0.5:source`. Дополнительные команды передаются через `--extra`.
- Пути в макросе и в командной строке передаются относительно папки программы. Абсолютный путь пользователя содержит кириллицу (`C:\Users\Андрей\...`), а Geant4 открывает файлы через узкие строки.
- Логи каждого процесса — `<out>/logs/`, сгенерированные макросы — `<out>/macros/`.

**Воспроизводимость.** Зерно генератора для каждого прогона вычисляется из имени выходного файла (шаг 003). Поэтому параллельные процессы не дают одинаковых событий, а повторный запуск той же серии даёт те же результаты.

## Проверка и результат

- **Цепочка `compare.mac`** при 30 событиях на точку отработала без ошибок и создала 42 файла: 3 материала × 2 формы × 7 положений.
- **Пробная серия** через `run_tof_campaign.py`: 3000 событий на точку, 6 конфигураций параллельно, Intel Core i5-12450H.

  | Конфигурация | Время на все 7 точек | мс/событие |
  |---|---|---|
  | PbF₂ (box, trd) | 0.2 мин | ~0.4 |
  | BGO (box, trd) | ~1 мин | ~2.5 |
  | LYSO (box, trd) | ~20 мин | ~30, при полной загрузке процессора до ~80 |

- **Число событий по умолчанию — 20 000 на точку.** Совпадения «1+1» составляют ~8 % событий, так что это ~1 500 совпадений и CTR с точностью ~5 %. Для LYSO это ~10 минут на точку, полная серия из 6 конфигураций — около 1.5–2 часов. Таблица времени счёта приведена в README.
